# 어디에 버리지? — 시민·AI·행정이 함께 키우는 생활폐기물 배출안내

> **시민의 검색 실패 데이터를 AI가 분석하고, 공무원이 검토하여 행정 데이터베이스를 지속적으로 개선하는 시민참여형 AI 행정서비스**

부산광역시 16개 구·군의 생활폐기물 배출 방법, 요일별 배출 안내, 수거업체 문의, 대형폐기물 신청을 5개 언어로 한 화면에 안내하는 웹앱(PWA)입니다.
시민이 찾지 못한 검색어는 자동으로 모이고, AI 모델 2종이 이를 분석해 등록 후보를 만들면, 공무원이 검토해 행정 DB에 반영합니다. **시민이 이용할수록 안내가 정확해지는 구조**입니다.

동구청 환경청소위생과 근무 당시 직원이 별도 개발용역·신규 개발예산 없이 직접 개발했고, 부산광역시로 옮긴 뒤 부산 16개 구·군으로 확장했습니다.

관리자 대시보드는 로그인 화면에서 **"심사위원 로그인 (이메일)"** 을 펼쳐 구동안내서에 적힌 심사용 계정으로 들어갑니다. 읽기 전용 임시 계정이며 심사 종료 후 삭제합니다. ('Google 계정으로 로그인'은 지정 공무원 전용입니다.)

### 시민 화면에 AI가 보이지 않는 이유
시민에게는 **공무원이 확인한 행정 DB의 답만** 보여 줍니다. AI는 관리자 화면에서 검색 실패를 분석해 공무원의 등록 판단을 돕는 역할만 합니다.
공무원이 확정한 품목 30개를 기존 DB 정보 없이 AI에 물었을 때 Gemini 67%, Solar 53%만 맞혔고, 틀린 품목(달걀껍데기·생선뼈·커피찌꺼기 등)이 시민이 가장 많이 찾는 품목과 겹쳤기 때문입니다.

### 핵심 흐름 (시연영상 순서)

```
 [흐름 1] 시민                 [흐름 2] AI 분석               [흐름 3] 공무원 검토·반영
 품목 검색 ──실패──▶ 실패 검색어 ──▶ Gemini·Solar 동시 분석 ──▶ 비교·확인 후 data.js 반영
    ▲               자동 기록          (분류·등록 필요 여부·           │
    │             + 카카오톡 제보        5개 언어 등록 후보)            │
    └───────────── 같은 검색어가 정확히 안내됨 (✅ 추가 완료) ◀────────────┘
```

1. **시민**: 구·군 선택 → `달걀껍데기` 검색(정확히 안내) → `마늘` 검색('유사 품목'으로 구분 표시) → `페트병` 검색(환경부 『분리의 정석』 품목사전으로 연결) → 언어·구·군 전환 → 찾지 못하면 카카오톡 채널 제보
2. **관리자**: 대시보드의 **검색 실패 목록**에서 품목 옆 **AI 분석** → 비교 창 왼쪽 Gemini·오른쪽 Solar의 분류, 등록 필요 여부, 근거, 5개 언어 등록 후보 확인 (Solar는 10초 안팎 걸릴 수 있음)
3. **반영**: 등록 후보의 **복사**(`data.js` 한 줄 형식) → 공무원이 확인해 `data.js`에 붙여 넣고 배포 → 시민 화면에서 같은 검색어가 정확히 안내되고, 실패 목록에 `✅ 추가 완료` 표시
   - 심사용 계정은 읽기 전용이라 흐름 3은 시연영상('사탕' 등록 전후)으로 확인할 수 있습니다.

### 관리자 대시보드 (`/admin`)
- 총·오늘 검색 수, 검색 성공률, QR 유입률, 최근 7일 추이, 언어별·유형별 현황, 인기 검색어, CSV 내보내기
- **검색 실패 목록**: 최근 300건을 같은 검색어끼리 합쳐 횟수 표시. 이미 반영된 검색어는 `✅ 추가 완료`, AI가 등록 대상이 아니라고 본 검색어는 `등록 대상 아님`, 두 모델 판단이 엇갈리면 `검토 필요`
- **AI 비교 분석**: Gemini·Solar에 동시에 요청해 나란히 표시. 한 모델이 실패해도 다른 모델 결과는 그대로 표시
- 대시보드가 현재 DB에서 찾은 **정확히 일치·유사 품목**을 AI에 함께 보내, 이미 있는 품목을 다시 등록하라고 하지 않도록 함

## 🤖 AI 구성과 모델 교체·추가

AI 호출은 Supabase Edge Function 한 곳(`supabase/functions/ai-analyze-failed-search/index.ts`)에서만 합니다. API 키는 브라우저에 두지 않습니다.

| 모델 | 기본값 | 키 |
|------|------|------|
| Google Gemini | `gemini-3.5-flash-lite` | `GEMINI_API_KEY` |
| Upstage Solar (구조화 출력) | `solar-pro4` | `UPSTAGE_API_KEY` (또는 `SOLAR_API_KEY`) |

| Secret | 용도 |
|------|------|
| `GEMINI_MODEL` / `SOLAR_MODEL` | 모델명 변경 (선택) |
| `AI_PROVIDER` | 요청에 모델 지정이 없을 때 기본 모델 (`gemini` / `solar`, 기본 `gemini`) |
| `ADMIN_EMAILS` | AI 분석을 호출할 수 있는 관리자 이메일 (쉼표 구분) |

**교체·추가 방법**
- 같은 회사의 다른 모델: 모델명 Secret만 변경 (코드 수정 없음)
- 다른 회사 모델(Claude·GPT·공통기반 모델 등):
  1. `callGemini()`·`callSolar()`와 같은 형식의 호출 함수 1개 추가
  2. 제공자 목록(`PROVIDERS`)과 호출 분기에 이름 추가
  3. Supabase Secret에 API 키 등록
  - 프롬프트·결과 형식·화면·DB는 그대로 사용합니다. Solar 호출부가 OpenAI 호환 형식(chat completions)이라, 같은 형식의 모델은 주소·키 이름만 바꿔 연결할 수 있습니다.
- 구동을 확인한 모델은 Gemini·Solar 2종입니다. 비교 창은 두 칸이라, 세 번째 모델을 나란히 보려면 대시보드 비교 칸도 추가해야 합니다.

```bash
npx supabase secrets set UPSTAGE_API_KEY=... SOLAR_MODEL=solar-pro4
# Windows에서는 작업 폴더 밖에서 --workdir 로 지정 (폴더의 supabase.js 와 이름이 겹치지 않도록)
npx supabase functions deploy ai-analyze-failed-search --project-ref <프로젝트 ref> --workdir <작업 폴더 경로>
```

AI 판단은 `ai_analysis_results` 표에 저장됩니다(검색어·언어·모델·판단만, 개인정보 없음). 표는 `supabase/ai-analysis-results.sql`을 SQL Editor에서 한 번 실행해 만듭니다.

## 🏙️ 다른 지자체 도입 방법

품목 정보와 지역 정보가 파일로 나뉘어 있어, 배출기준이 다른 지자체는 **두 파일만 교체**하면 됩니다.

| 파일 | 내용 | 바꿀 것 |
|------|------|------|
| `data.js` | 품목 DB (5개 언어) — 부산시 기준, 16개 구·군 공통 | 해당 지자체 배출기준 |
| `districts.js` | 구·군별 공식 누리집, 배출요일 이미지, 수거업체, 대형폐기물 | 해당 지자체 구·군 정보 |

```js
// districts.js 한 구·군 예시
{
  id: "donggu",
  name: "동구",
  scheduleImages: { ko: "schedule-ko.jpg", en: "schedule-en.jpg", ... },
  contacts: [{ area: "...", areaEn: "...", tel: "...", label: "..." }],
  bulk: [{ area: "...", tel: "...", url: "...", urlLabel: "..." }],
  foodstoreUrl: "...",   // 음식물 전용용기 판매소 지도 링크
  stickersaleUrl: "..."  // 납부필증 판매소 지도 링크
}
```

자체 Supabase로 옮길 때는 `supabase.js`·`app.js`·`admin/*.js`의 `SUPABASE_URL`·`SUPABASE_KEY`를 새 프로젝트 값으로 바꾸고, `supabase/` 폴더의 SQL을 실행한 뒤 Edge Function을 배포합니다.

## 🔒 개인정보·보안
- 공개(anon) 키도 제출 저장소에는 두지 않고, 데이터 접근은 RLS 권한으로 제한합니다.
- 회원가입·개인 식별 정보를 받지 않습니다. 검색 기록은 검색어·결과 유형·언어·유입 경로(QR/웹)만 저장합니다.
- 검색 기록과 AI 판단은 RLS로 허용된 관리자 계정만 조회할 수 있고, AI 판단 저장은 서버 함수만 할 수 있습니다.
- AI 분석 함수는 관리자 로그인 토큰과 `ADMIN_EMAILS`로 호출자를 확인합니다.
- 대시보드 출력은 HTML 이스케이프로 XSS를 막습니다.
- 외부 서비스(『분리의 정석』, 카카오톡 채널, 지도)는 식별 정보를 넘기지 않는 링크 방식으로 연결합니다.

## ⚠️ 알려진 제약 사항
- AI 결과는 등록 후보(초안)이며, 다국어 초안에도 오번역·빈칸이 있을 수 있어 공무원 확인 후 반영합니다.
- 품목 반영은 `data.js` 수정 후 배포하는 방식이며, 관리자 화면에서 바로 저장하는 기능은 없습니다.
- 외국어 배출요일 이미지는 동구·남구·강서구·사상구(4개 언어), 금정구(영·중)에만 있고, 나머지 구·군은 외국어 화면에서도 한국어 이미지가 표시됩니다.
